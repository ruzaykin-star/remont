# Ремонт-трекер — общий доступ

Это тот же трекер, что вы делали в чате с Claude, но перенесённый в отдельный
проект, который можно захостить где угодно и дать ссылку нескольким людям.
Данные (расходы, задачи, покупки и т.д.) хранятся в общей базе Supabase, а не
в приватном хранилище Claude — поэтому все, кто открыл ссылку, видят одни и те
же данные и изменения появляются друг у друга почти сразу (без перезагрузки
страницы).

## Что нужно сделать (один раз)

### 1. Supabase — общая база данных

1. Зайдите на [supabase.com](https://supabase.com) и создайте бесплатный аккаунт/проект.
2. В проекте откройте **SQL Editor -> New query**, вставьте содержимое файла
   [`supabase.sql`](supabase.sql) из этой папки и нажмите Run.
3. Откройте **Project Settings -> API** и скопируйте:
   - `Project URL` → это будет `VITE_SUPABASE_URL`
   - `anon public` ключ → это будет `VITE_SUPABASE_ANON_KEY`

### 2. Переменные окружения

Скопируйте `.env.example` в `.env.local` и вставьте туда значения из
Supabase. `VITE_PROJECT_ID` уже сгенерирован — можно оставить как есть, это
просто "имя комнаты" для ваших данных.

```bash
cp .env.example .env.local
```

Эти же три переменные (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`,
`VITE_PROJECT_ID`) нужно будет добавить в настройках Vercel — см. ниже.

### 3. GitHub

Создайте пустой репозиторий на [github.com/new](https://github.com/new) (можно
приватный) и запушьте туда этот проект:

```bash
git remote add origin <ссылка-на-ваш-репозиторий>
git push -u origin main
```

### 4. Vercel — деплой

1. Зайдите на [vercel.com](https://vercel.com), войдите через GitHub.
2. **Add New -> Project**, выберите репозиторий `remont-tracker`.
3. Vercel сам определит, что это Vite-проект. Перед деплоем откройте
   **Environment Variables** и добавьте те же три переменные, что в
   `.env.local`.
4. Нажмите **Deploy**. Через минуту получите ссылку вида
   `https://remont-tracker-xxxx.vercel.app` — вот её и отправляйте всем, кому
   нужен доступ.

Дальше при каждом `git push` в GitHub Vercel будет пересобирать сайт
автоматически.

## Важно про доступ и безопасность

- Ссылку видит любой, у кого она есть — отдельных логинов/паролей нет, как и
  в оригинальном варианте.
- Технически человек, открывший "инструменты разработчика" в браузере, может
  увидеть `VITE_SUPABASE_ANON_KEY` и `VITE_PROJECT_ID` и напрямую читать/писать
  эту запись в базе. Для семейного трекера ремонта это обычно некритично, но
  это не банковский уровень защиты. Если захотите настоящую защиту паролем —
  можно добавить Supabase Auth (email+пароль), скажите, помогу.

## Локальный запуск (проверить перед деплоем)

Нужен установленный Node.js (18+). В этой сессии Node недоступен, поэтому
собрать и проверить проект локально я не смог — но Vercel соберёт его сам при
деплое. Если хотите проверить у себя:

```bash
npm install
npm run dev
```
